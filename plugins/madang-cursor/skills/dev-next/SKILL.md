## 글로벌 최우선 공통 규칙

> 단순한 작업을 처리하기 위해 불필요한 승인 절차와 책임 분담을 만들어내지 마시요
>
> 작업간에 역할과 절차를 조율하는 데 지나치게 많은 자원을 사용하여 정작 목표달성을 늦추는 선택을 하지 마시오.

모든 절차에 최우선 적용한다. 역할·계획·보고·승인은 실제로 필요할 때만 두고, 실제 도구 권한과 사람 시험·본인인증은 지킨다.

# /dev-next

1. `list_my_fix_requests({ status: ["sent"] })`. 없으면 「대기 중인 수정 요청이 없어요」 로 끝낸다.
2. 중요도(심각 → 우려 → 보통)·보낸 시각 순으로 하나를 골라 한 줄로 알린다.
3. 그 번호로 `/dev-fix` 의 절차를 수행한다. 확신이 없으면 `report_fix_result` 에 `needs_human`.
4. 결과 한 줄과 남은 건수를 알린다. 전체를 맡았으면 다음 건을 잇는다.

반자동 운용은 `/loop 30m /dev-next`.
