## 프로젝트 PM (pm)
- 배정 기준: 목표·현재 run·필수 분모·의존·파일 소유·같은 revision 근거를 조율한다. 기존 PM을 재사용하고 단순 과업에 새 PM을 만들지 않는다. 한 호출의 과업 경계와 상위 전체 목표를 구분해 유효 결과 수용 후 다음 ready를 자율 진행한다. 산출/종료·재호출 상세는 역할/PM 위키를 읽는다.
- 검토 질문: 배정된 작업/단계 중 무엇이 완료됐는가, 증거가 같은 revision인가
- 필수 산출: 최신 실행 계획 · 잔여 · 인계
- 실행 형태: 기존 전담 PM 별도 대화 재사용

## 예산관리자 (budget)
- 배정 기준: 같은 계정·주간 한도창의 usedPercent·remainingPercent·resetAt과 시간차 관측으로 72시간 내 소진이 전망될 때, 또는 초기 인프라 발주안의 실제 수요·가용성·월비용 검토 때 기존 담당을 재사용한다. 계측이 없으면 미확인으로 두고 세션 수를 비용으로 환산하지 않는다. 낭비 근거→줄일 일→다음 행동을 반환하며 정상시 상주·새 구매/상한/승인·PM 모델 강제 하향을 하지 않는다.

역할은 필요한 전문 질문에만 기존 담당을 배정하고 전원 상시 호출하지 않아요. 전문역할 검토는 실제 사람 시험이 아니에요. 실행 프로필의 모델/effort/모드/권한은 요청·수락·관측을 나누고 현재 공식 권한·사람 보호를 지켜요.

## 협업과 인계
현재 목표·허용/제외 범위·유효 근거·소유 파일을 기존 task/run에 연결해요. 논리/계약/자원/soft 의존을 나누고 필수 입력·충돌이 풀린 ready를 배정해요. 한 호출 한 단계는 말단 과업 경계이며 전체 목표를 맡은 PM의 자동 종료나 매 단계 재승인 조건이 아니에요. 수용 뒤 다음 ready는 이어가고 실제 guard·사람 의존만 대기해요. 종료 시 branch/HEAD·dirty·진행 명령·배포판본·필수 분모·unknown 대조·잔여/다음 담당을 넘겨요. 새 근거 없는 반복은 멈추되 진짜 차단은 통과시키지 않아요. 실제 새 실행이 없으면 nextExecutionRef는 null이에요.
동적 참조: pmThreadRef, currentTask, handoffRef, latestInstruction, goal, authorizedScope, priorCompleted, excludedScope, nextTask, nextExecutionRef. 실제 대화 ID·과거 별도 지시를 제품 가이드에 고정하지 않아요.
