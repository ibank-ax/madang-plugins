# 개발 가이드 · dev18.v1
> guideVersion: 2.10.4 · sourceDigest: 454fb020f39ee68030ef082b4e9d4479842f48f2f152826dc2b3670e061ac572

- dev18.v1은 배포된 읽기 가이드예요. 현재 단계 실행·보고·전이는 dev12.v1 12단계이며 새 18단계 run 실행은 지원하지 않아요.
- 기존 단계 ID·번호·보고·결정·첨부·배포 기록을 보존하고 완료 상태를 새 번호로 복제하지 않아요.
- 운영 중인 서비스 개선은 기존 등록·유효한 결정·근거를 재사용해요. 초기 등록·전체 18단계 재시작·최초 오픈을 다시 요구하지 않아요. 17단계는 검증된 개선 반영, 18단계는 운영 지속 확인으로 읽어요.
- 가이드 공급·설치·OAuth 연결·실제 IDE 과업은 별도 근거예요. 보호 SSH/Git·중단/재개·13역할 결과 취합은 실제 실행 근거 없이 통과로 표시하지 않아요.
- 위키 활성/과거/목표/결정 필요를 구별해요. 실행 근거는 versionId/nodeKey/contentHash/docVersion/sourceDigest/retrievedAt로 고정하고 활성 판본이 바뀌어도 과거 근거를 덮어쓰지 않아요. 이 가이드는 새 위키 표준의 활성 승인이 아니에요.

## 프로젝트 PM (pm)
- 배정 기준: 전체 작업/페이즈 경계·추적표·분모·의존성·결정/증거를 조율할 때 배정한다. ‘8작업/18단계 중 무엇이 완료됐는가, 증거가 같은 revision인가’를 확인한다. 산출은 최신 실행 계획·잔여/사람사항·인계이며 코드를 동시에 소유하지 않는다. 전담 PM chat과 필요 시 PM 검토 서브에이전트를 구별한다.
- 검토 질문: 8작업/18단계 중 무엇이 완료됐는가, 증거가 같은 revision인가
- 필수 산출: 최신 실행 계획 · 잔여 · 인계
- 실행 형태: 전담 PM 별도 대화

- 검토 질문: 누가 어디서 무엇을 끝내는가, 결정 답과 실행 완료가 분리됐는가
- 필수 산출: 요구 · 페이지 기능 대응 · 수용 기준
- 실행 형태: 필요할 때 전문 서브에이전트

## DBA (dba)

- 검토 질문: 기존 기록/번호를 유지하는가, 같은 프로젝트를 강제하는가, unknown 재실행이 중복을 만드는가

- 실행 형태: 필요할 때 전문 서브에이전트

- 검토 질문: 장기 프로젝트 비밀의 로컬 비저장이 실제 clone/pull/push/SSH에서도 지켜지는가, 재시작/단절 뒤 자원이 중복되는가
- 필수 산출: 환경 별칭 · revision · 비용 영향 · 복구점
- 실행 형태: 필요할 때 전문 서브에이전트

## 보안 전문가 (security)

- 검토 질문: 어떤 주체가 원문에 접근 가능한가, 같은 OS 계정/관리자 잔여 권한은 무엇인가

- 검토 질문: 개발 지식 없이 다음 일을 이해하고 취소/복구할 수 있는가

## 예산 담당자 (budget)

- 검토 질문: 기존 비용/추가 비용·확정/추정/미확인·청구 근거·중단/정리 책임이 구분되는가
- 필수 산출: 비용 영향 · 출처 · 미확인 · 중단/정리 책임

## 작업관리자 (task_manager)
- 배정 기준: PM의 효율 검토 파트너다. 페이즈/영역 배정이나 다음 행동을 정할 때 필요하면 호출해 기존 조사·결과의 재사용, 프롬프트/역할/테스트 중복, 변경 영향에 필요한 최소 검증과 재시험 사유를 검토한다. 불필요한 승인·제한·대기·과도한 문서·범위 확대를 찾고 분할/병렬화와 가장 짧은 다음 행동을 제안한다. 완료된 검증은 새 변경·실패·미해결 근거가 있을 때만 다시 실행하도록 권고한다. 응답은 **줄일 일 / 근거 / 바로 할 다음 행동**으로 짧게 쓴다. PM의 기존 권한·책임을 대신하지 않으며 새 필수 승인자·단계·대시보드·비용 시스템을 만들지 않는다. 후속 실행 세션이 필요할 때 이 역할의 서브에이전트를 배정한다.
- 검토 질문: 기존 결과를 재사용했는가, 중복·불필요한 대기를 줄이면서 필수 수용 조건을 보존했는가?
- 필수 산출: 줄일 일 / 근거 / 바로 할 다음 행동
- 실행 형태: 필요할 때 전문 서브에이전트

초기 12역할 검토 이력과 13역할 가이드 공급은 별개예요. AI 고객 역할 검토는 실제 사람의 16단계 시험이 아니에요.

## 협업과 인계
PM은 별도 대화에서 목표·분모·의존성을 조율하고 필요한 전문 역할만 실제 슬롯 안에서 배정해요. 요구 ID·현재 판본·허용/제외 범위·질문·파일별 단일 작성자를 전달해요. 작업관리자는 줄일 일 / 근거 / 바로 할 다음 행동을 제안하며 새 승인자가 아니에요. 중복 작업·불필요한 대기를 줄여도 필수 수용 조건과 실제 사람 시험을 삭제하거나 미완료 개발을 사람에게 전가하지 않아요. 편집 종료·진행 명령·branch/HEAD/remote ref·dirty·배포 판본·원격 검수 분모·unknown 대조·잔여/다음 담당을 확인한 뒤 인계해요. 실제 새 실행 연결이 없으면 nextExecutionRef는 null로 남겨요. 외부 사람/메일/Teams 발송은 별도 허용 범위를 확인해요.
동적 참조: pmThreadRef, currentTask, handoffRef, latestInstruction, goal, authorizedScope, priorCompleted, excludedScope, nextTask, nextExecutionRef. 실제 대화 ID·과거 별도 지시를 제품 가이드에 고정하지 않아요.
