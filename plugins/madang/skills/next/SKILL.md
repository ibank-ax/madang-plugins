## 글로벌 최우선 공통 규칙

> 단순한 작업을 처리하기 위해 불필요한 승인 절차와 책임 분담을 만들어내지 마시요
>
> 작업간에 역할과 절차를 조율하는 데 지나치게 많은 자원을 사용하여 정작 목표달성을 늦추는 선택을 하지 마시오.

이 두 원칙은 DEV.MADANG의 모든 스킬·역할 가이드·작업 절차를 해석할 때 최우선으로 적용한다. 단순한 작업은 현재 담당 에이전트가 바로 완료하고, 추가 역할·회의·계획·보고·승인은 목표 달성에 실제로 필요한 경우에만 둔다. 기존 권한·사용자 결정·근거·세션을 재사용하며, 역할을 배정하기 위한 역할이나 절차를 관리하기 위한 절차를 만들지 않는다. 협업은 혼자 처리하는 것보다 완료 시간이나 품질을 개선할 때만 사용한다. 현재 DEV 정책이 `autonomous`이면 에이전트가 위임된 연결·자격·설정·Git·버킷 관리·백업·배포를 판단·승인·실행한다. `operational`이면 고정 범위에 대해 사람 확인을 한 번 받고 같은 범위의 검사·적용을 자동으로 잇는다. 환경명·서버 가동·예전 단계 이름으로 운영 전환 여부를 추정하지 않는다. 실제 도구 권한과 사람 시험·본인인증은 지킨다.

# /dev:next

나에게 배정된 수정 요청을 하나씩 끝낸다.

1. `list_my_fix_requests({ status: ["sent"] })` 로 대기 건을 가져온다. 없으면 「대기 중인 수정 요청이 없어요」 라고만 답하고 끝낸다.
2. 중요도(심각 → 우려 → 보통)와 보낸 시각 순으로 하나를 고른다. 무엇을 고를지 한 줄로 알리고 시작한다.
3. 그 이슈 번호로 `/dev:fix` 의 절차를 그대로 수행한다(패킷 읽기 → start_fix → 브랜치 → 수정 → 테스트 → PR → report_fix_result).
4. 한 건이 끝나면 결과를 한 줄로 요약하고 남은 건수를 알린다. 사용자가 전체 대기 작업을 맡겼다면 다음 허용 건을 계속한다. 한 건만 맡겼다면 해당 결과를 메인 에이전트 또는 사용자에게 반환한다. 각 프로젝트에서는 `/dev:collaborate`의 세션·수신함·회신 절차를 적용한다.

확신이 없으면 고친 척하지 말고 `report_fix_result` 에 `needs_human` 으로 보고한다.

반자동 운용은 `/loop 30m /dev:next`.
